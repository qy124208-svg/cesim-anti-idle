# Cesim 防挂机助手

一个浏览器扩展（Manifest V3，Chromium 通用，**Edge / Chrome 均可用**），在 Cesim 操作界面（`*.cesim.cn`）自动上下滚动、程序化点击、模拟鼠标活动并发送**心跳请求**，用于维持页面活跃、规避长时间挂机导致的登录失效。支持切走标签页后**后台继续挂机**。

> **为什么不干扰你的鼠标**：扩展全程只调用页面脚本的 `element.click()` 与合成 `MouseEvent`，**从不移动真实鼠标光标、从不调用系统级鼠标 API**（如 CDP `Input.dispatchMouseEvent`、Windows `SetCursorPos`/`mouse_event`）。因此你在其他窗口正常移动、点击鼠标完全不受影响，也不会动任何鼠标驱动。

## 安装（Edge）

1. 打开 Edge，地址栏输入 `edge://extensions`。
2. 左侧打开「开发人员模式」开关。
3. 点击「加载解压缩的扩展」。
4. 在弹窗里导航到 `cesim` 目录，**单击选中 `cesim-anti-idle` 文件夹（不要双击进去）**，点「选择文件夹」。
   - 注意：Edge 的这个「选择文件夹」弹窗**只显示文件夹、不显示文件**，双击进去看到「空」是正常的，不影响加载。
5. 打开/刷新 `zjgsu.cesim.cn` 的任意操作页面，扩展即自动生效（图标会显示「开」徽标）。

> Chrome 用户同样适用：步骤改为 `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」即可。

## 使用

点击工具栏的扩展图标打开设置面板：

- **自动滚动（总开关）**：关闭后立即停止所有活动。
- **滚动频率**：慢（30~60s）/ 中（15~45s）/ 快（8~20s），每次在区间内随机。
- **滚动幅度**：小（80~350px）/ 中（150~700px）/ 大（300~1200px），默认「大」。
- **后台保活（防节流）**：默认开启，让切到其他标签页/窗口后仍保持滚动频率。
- **模拟鼠标移动**：勾选后，每次滚动同时派发一次随机 `mousemove`（合成事件，仅前台，不移动真实光标）。
- **自动点击**：默认关闭（v1.2.0 起：心跳请求已足够续 session，点击会切换视图、挂机时反可能乱跳）。开启后只程序化点击「导航页签」（`[role="tab"]` / `[role="menuitem"]`），模拟真人浏览。
- **点击频率**：慢（5~10 分钟）/ 中（3~6 分钟）/ 快（1~3 分钟）。
- **心跳请求（防掉线）**：默认开启。带登录凭证重新请求当前页面，向服务器证明「我还活着」，这才是真正防 session 超时掉线的关键。
- **心跳频率**：慢（15~25 分钟）/ 中（8~15 分钟）/ 快（4~8 分钟）。

## 自动点击怎么保证「安全」

- **只点导航页签**：`[role="tab"]` / `[role="menuitem"]`。点击只切换视图并产生请求，不整页跳转。
- **彻底不点 `a[href]`**（会整页跳转 → 刷新 → 重注入的循环）**和普通 `button`**（可能是提交/删除等有副作用的操作）。
- 用**危险词黑名单**过滤（提交/确认/保存/删除/重置/清空/发送/下单/支付/结算/退出/登出…），命中绝不点，避免误提交决策或退出登录。
- 排除不可见元素（`display:none` / `visibility:hidden` / 尺寸过小）。

## 为什么加了点击和心跳（而不是只滚动）

上一版只有滚动 + 合成鼠标事件。**滚动和合成事件都只是前端活动，不产生任何网络请求**。如果 Cesim 的登录失效是服务器端 session 空闲超时（固定时间一到就踢），那纯滚动无论前后台都无法续命。本版新增两层：

1. **自动点击**：点击导航 tab 会触发 Cesim 前端切换视图 → 真实网络请求，模拟「真人时不时点一下」。
2. **心跳请求**：独立于点击，周期性 `fetch` 当前页面（带 session cookie、绕过缓存），是维持 session 最直接的兜底。

## 后台挂机是怎么做到的（三层保险）

1. **AudioContext 静音保活**：页面内播放一个极低音量（25Hz、音量 0.01）的持续音频，让浏览器认为本页在「发声」，从而不对其定时器做节流——切走标签页后，滚动仍能保持频率。
2. **`chrome.alarms` 后台兜底**：扩展后台每 30 秒向 Cesim 页面发一次 tick，检查滚动/点击/心跳是否逾期并补触发。
3. **心跳请求**：即使前两层都失效，只要页面还活着，心跳就会持续发真实请求续 session。

## 重要限制（务必读）

- **后台保活需要「激活」一次**：浏览器 autoplay 策略要求首次用户交互后才能播放音频，所以**首次使用时在 Cesim 页面上点一下鼠标**（登录、随便点一下都行），之后音频保活才生效。
- **最小化整个浏览器**：切走标签页/切到别的窗口都可以维持；但「最小化整个浏览器窗口」可能触发系统级节流，音频保活不一定压得住。建议开两个窗口：一个放 Cesim 挂机、一个干别的。
- **自动点击可能切换视图**：点击 Cesim 导航 tab 会切换到对应页面。若你正在填写未保存的决策，请**先保存**再挂机（挂机场景本就应无未保存表单）。点击不会提交数据、不会点危险按钮。
- **心跳是「尽力而为」**：若 Cesim 是严格固定空闲超时且不认普通请求、只认特定心跳/自动保存接口，那通用 `fetch` 可能不够。遇到仍掉线的情况，把 F12 网络面板里「掉线前最后一次成功的请求」发我，我改成对接它。

## 文件清单

- `manifest.json`：扩展清单（MV3，权限 storage + alarms）
- `background.js`：图标徽标 + 每 30 秒 alarm 心跳兜底
- `content.js`：核心逻辑（滚动 + 程序化点击 + 鼠标模拟 + 心跳请求 + 音频保活 + tick 响应）
- `popup.html` / `popup.js`：设置面板
